# ערכת הטיפול בטעויות של Claude Code

קלוד אומר "צודק, טעיתי", ושבוע אחר כך טעות מאותו סוג חוזרת. הערכה הזו הופכת כל תיקון לרשומה ביומן, דפוס שחוזר לכלל שנטען בתחילת כל סשן, וכלל שלא עבד לבדיקה מכנית.

הדף עם כל הפרומפטים והבקרות: https://guycoful.github.io/claude-mistakes-kit/

## מה בפנים
- hooks ב-3 אירועים: UserPromptSubmit מזהה תיקון ונותן לו מזהה (לפי ביטוי, ובנוסף סיווג בהקשר ברקע), Stop בודק שהמזהה נרשם ביומן, SessionStart טוען את הלקחים הפעילים.
- יומן טעויות בפורמט קבוע, וקובץ לקחים פעילים.
- סקיל ל-Claude Code שמתקין, רושם, מציג מצב ומכין קובץ לבדיקה שבועית וחודשית.
- פרומפט התקנה אחד ו-6 בקרות שבודקות שהמערכת עובדת.

הכול רץ בתוך הפרויקט. אין שרת ואין חיבור חיצוני.

## איך זה עובד
1. אתם כותבים לקלוד "טעית" או "כבר אמרתי". ה-hook רושם את ההודעה ב-`lessons/candidates.jsonl`, נותן לתיקון מזהה (למשל `#mk-4f2a91`) ומזריק לקלוד הנחיה לרשום את הטעות לפני שהוא עונה. תיקון שנכתב בלי אחד הביטויים נתפס בנוסף בסיווג ברקע (ראו "סיווג בהקשר").
2. קלוד כותב רשומה ב-`lessons/MISTAKES.md`: ציטוט, הכלל שנשבר, מה בודקים בפעם הבאה, מוסר השכל, ומה שונה בפועל.
3. ה-Stop hook בודק שהמזהה מופיע ביומן. אם לא, הוא עוצר את סיום התשובה ומבקש רשומה. הוא חוסם פעם אחת בכל תשובה, כדי שלא תהיה לולאה.
4. פעם בשבוע אתם מדביקים את היומן בצ'אט של מודל מחברה אחרת, כמו ChatGPT או Gemini. הוא מחפש סיבות שורש ודפוסים שחוזרים, ומציע כלל. ההדבקה ידנית, ואין אינטגרציה.
5. כלל שאישרתם נכנס ל-`lessons/LESSONS_ACTIVE.md`. ה-SessionStart hook טוען אותו בתחילת כל סשן.
6. פעם בחודש בודקים אם הטעות חזרה אחרי שהכלל נוסף. אם חזרה, הכלל לא עובד, ומחליפים אותו בבדיקה מכנית.

דוגמה מסשן:
```
> טעית, כבר אמרתי לך שהקובץ נקרא config.yaml
[טיפול בטעויות] בהודעה הזו יש תיקון, והמזהה שלו #mk-4f2a91.
● רושם ב-lessons/MISTAKES.md:
04.11.2026 | #mk-4f2a91 | "השתמשתי ב-config.yml" | שם הקובץ לא נבדק | ls לפני שימוש בקובץ | לא
● הקובץ הוא config.yaml. ממשיך איתו.
```

## התקנה
דרך 1: פרומפט אחד. פותחים Claude Code בתיקיית הפרויקט ומדביקים את הפרומפט מהדף. קלוד מתקין הכול ומראה כל שינוי לפני שהוא עושה אותו.

דרך 2: סקיל. בטרמינל, בתיקיית הפרויקט:
```bash
git clone https://github.com/guycoful/claude-mistakes-kit.git /tmp/mk
cp -r /tmp/mk/skill/claude-mistakes-kit ~/.claude/skills/
python3 ~/.claude/skills/claude-mistakes-kit/scripts/install.py "$PWD"
```
המתקין לא מוחק ולא דורס. הוא ממזג hooks בלי לשכפל, שומר גיבוי של `settings.json` כשהוא משתנה, ומתקין את ה-hook של הערכה בשם נפרד אם כבר יש שם hook אחר. התקנה חוזרת בטוחה.

אחרי ההתקנה פותחים סשן חדש, כי hooks נטענים בתחילת סשן.

## סיווג בהקשר
הזיהוי לפי ביטויים מפספס תיקון שנכתב במילים אחרות. לכן ה-hook מריץ ברקע (async), על כל הודעה שאין בה ביטוי, את `claude -p --model haiku` ושואל אם ההודעה מתקנת את קלוד לפי ההקשר. תיקון נספר רק כשהמסווג מצטט מילים שבאמת מופיעות בהודעה, וספק נחשב NO. תיקון שנספר מקבל מזהה, וה-Stop hook דורש עליו רשומה.
- כל הודעה בלי ביטוי נשלחת לקריאה נוספת של מודל קטן, עם מגבלת זמן של 90 שניות.
- שגיאות נכתבות ל-`lessons/.classify-errors.log`.
- כיבוי: `MK_CLASSIFY=off`.

## פקודות הסקיל
| מה | פקודה |
|---|---|
| התקנה | `python3 ~/.claude/skills/claude-mistakes-kit/scripts/install.py "$PWD"` |
| מצב היומן | `python3 ~/.claude/skills/claude-mistakes-kit/scripts/status.py "$PWD"` |
| קובץ לבדיקה שבועית | `python3 ~/.claude/skills/claude-mistakes-kit/scripts/review_bundle.py weekly "$PWD"` |
| קובץ לבדיקה חודשית | `python3 ~/.claude/skills/claude-mistakes-kit/scripts/review_bundle.py monthly "$PWD"` |

כל קובץ בדיקה נוצר עם תאריך ושעה בשם, ולא דורס קובץ קודם. לפני שמדביקים אותו במודל חיצוני, מוציאים ממנו שמות לקוחות, מפתחות ופרטים אישיים.

## 6 הבקרות
בלי הבקרות אין דרך לדעת אם המערכת עובדת או רק נראית מותקנת. הפקודות המלאות בדף.
1. ה-hook רץ: הודעה עם "טעית" מחזירה הנחיה, ולא נוגעת ב-`candidates.jsonl` שלכם. הבקרה בודקת גם את הסיווג בהקשר.
2. קלוד קוד רואה את ה-hooks: `/hooks` מציג UserPromptSubmit, Stop ו-SessionStart.
3. תיקון אמיתי נרשם: אחרי תיקון בסשן יש רשומה חדשה ב-`git diff lessons/MISTAKES.md`.
4. הלקחים נטענים: בסשן חדש קלוד מצטט את הכללים הפעילים.
5. תיקון שלא נתפס: מדפיסים את המועמדים של 7 הימים האחרונים ומשווים לתיקונים שכתבתם. חסר ביטוי? מוסיפים אותו ל-`MARKERS`.
6. הכלל באמת עובד: בבדיקה החודשית, כלל שאחריו הטעות חזרה מוחלף בבדיקה מכנית.

## מגבלות
- נבנה ל-Claude Code, כי הוא נשען על hooks.
- הזיהוי הראשי הוא לפי ביטויים. הרשימה `MARKERS` כוללת עברית ואנגלית, וכדאי להתאים אותה לאופן שבו אתם מתקנים. מילה כללית כמו "שוב" יוצרת התראות שווא. הסיווג בהקשר תופס חלק מהתיקונים שבלי ביטוי, ולא את כולם.
- ה-Stop hook בודק שהמזהה מופיע ביומן, ולא את איכות הרשומה. את האיכות בודקים אתם והבודק השבועי.
- קלוד כותב את הרשומה ונוטה לפרש את הטעות לטובתו. לכן הבדיקה השבועית נעשית במודל אחר.
- ספירת רשומות לא מוכיחה שטעות חזרה או לא חזרה. חזרה מוכחת צריכה ציטוט שנכתב אחרי שהכלל נוסף.
- היומן יושב ב-`lessons/` בשורש הפרויקט ולא תחת `.claude/`, כי Claude Code חוסם כתיבה לקבצים תחת `.claude/`.

## שאלות נפוצות
איך זה עובד עם ChatGPT או Gemini? אין חיבור. הסקריפט יוצר קובץ, ואתם מדביקים אותו בצ'אט חדש. מה שהמודל מציע, אתם מאשרים ידנית.

האם היומן יוצא מהפרויקט? רק כשאתם מדביקים אותו בעצמכם במודל חיצוני. עברו עליו לפני.

מה קורה בהתראת שווא? ה-Stop hook יבקש רשומה. כתבו רשומה קצרה "לא היה תיקון", עם הציטוט, והמזהה נסגר.

אפשר להשתמש בלי הסקיל? כן. הקבצים בתיקייה `kit/` מספיקים להתקנה ידנית: ה-hook, `settings.json`, תבניות היומן והסעיף ל-`CLAUDE.md`.

מה הערכה לא עושה? היא לא מבטיחה שטעות לא תחזור. היא עושה כל תיקון לנתון שאפשר לבדוק.
