שלושה צעדים


  1. פותחים את קלוד קוד בתיקיית הפרויקט, ומדביקים את פרומפט ההתקנה שלמטה. קלוד מתקין הכול ומראה לכם כל שינוי לפני שהוא עושה אותו.

  2. פותחים סשן חדש.

  3. מעכשיו, כשקלוד טועה, כותבים לו כרגיל "טעית" או "כבר אמרתי". הוא ירשום את הטעות ביומן לבד.

פעם בשבוע מדביקים את היומן ב-ChatGPT או ב-Gemini, עם הפרומפט של הבודק השבועי. זה כל מה שצריך. כל השאר בדף מיועד למי שרוצה לבדוק לעומק.

איך זה עובד

  1. hook של UserPromptSubmit מזהה בהודעה שלכם תיקון, כמו "טעית" או "כבר אמרתי". הוא רושם את ההודעה, נותן לתיקון מזהה, ומזריק לקלוד הנחיה לרשום את הטעות עם המזהה לפני שהוא עונה.
  2. הרשומה ב-MISTAKES.md כוללת ציטוט, הכלל שנשבר, מוסר השכל ומה שונה בפועל. אם לא שונה כלום, כותבים "טרם יושם". hook של Stop בודק שהמזהה של כל תיקון מהסשן מופיע ביומן. אם חסר מזהה, הוא עוצר את סיום התשובה ומבקש רשומה. הוא חוסם פעם אחת בכל תשובה, כדי שלא תהיה לולאה, וחוזר לחסום בתשובה הבאה עד שהמזהה מופיע. הוא בודק שהמזהה של התיקון מופיע ביומן, ולא את המבנה או האיכות של הרשומה. את זה בודקים אתם ובודק השבוע. היומן יושב ב-lessons/ בשורש הפרויקט ולא בתוך .claude/, כי קלוד קוד חוסם כתיבה לקבצים תחת .claude/. גילינו את זה בבדיקה בסשן אמיתי, כשקלוד ניסה לכתוב רשומה ונחסם.
  3. פעם בשבוע מודל של חברה אחרת עובר על היומן. הוא מחפש סיבת שורש ומה חוזר, ומציע כלל.
  4. כלל שאישרתם נכנס ל-LESSONS_ACTIVE.md. hook של SessionStart טוען אותו בתחילת כל סשן.
  5. פעם בחודש בודקים אם הטעות חזרה אחרי שהכלל נוסף. אם חזרה, הכלל לא עובד, ומחליפים אותו בבדיקה מכנית.

התקנה: פרומפט אחד לקלוד קוד

פותחים קלוד קוד בתיקיית הפרויקט ומדביקים:

תתקין לי בפרויקט הזה את ערכת הטיפול בטעויות. לפני כל שינוי בקובץ קיים, תראה לי את השינוי. אל תמחק ואל תדרוס קובץ קיים.
אם יש בפרויקט תיקייה .claude/lessons, זו גרסה קודמת של הערכה. במקרה כזה תעצור ותגיד לי להתקין דרך הסקיל, כי המתקין שלו משדרג בלי כפילויות.

1. תוריד את הקבצים האלה, בלי לשנות את התוכן:
https://raw.githubusercontent.com/guycoful/claude-mistakes-kit/main/kit/.claude/hooks/capture_correction.py
https://raw.githubusercontent.com/guycoful/claude-mistakes-kit/main/kit/lessons/MISTAKES.md

4. תריץ את בקרה 1 על ה-hook ששמרת בשלב 1, אחרי שתוודא שהתוכן שלו זהה לקובץ שהורדת. הבדיקה רצה בתיקייה זמנית, ולכן לא נוגעת ב-candidates.jsonl של הפרויקט:
echo '{"prompt":"טעית, כבר אמרתי לך"}' | CLAUDE_PROJECT_DIR="$(mktemp -d)" python3 .claude/hooks/<השם ששמרת>

למתקדמים: התקנה כסקיל ובקרות

הבקרות: איך יודעים שזה עובד

בלי הבקרות האלה אין לכם דרך לדעת אם המערכת עובדת, או שהיא רק נראית מותקנת.

1. ה-hook רץ

אחרי ההתקנה, בטרמינל בתיקיית הפרויקט:

( K=$(mktemp) || { echo "לא הצלחתי ליצור קובץ זמני. לא הרצתי כלום."; exit 1; }; curl -fsSL https://raw.githubusercontent.com/guycoful/claude-mistakes-kit/main/kit/.claude/hooks/capture_correction.py -o "$K" && [ -s "$K" ] || { echo "ההורדה של ה-hook נכשלה. לא הרצתי כלום."; exit 1; }; H=""; for f in .claude/hooks/capture_correction.py .claude/hooks/mistakes_kit_capture*.py; do [ -f "$f" ] && cmp -s "$f" "$K" && H="$f" && break; done; [ -n "$H" ] || { echo "לא נמצא hook זהה לקובץ של הערכה. לא הרצתי כלום."; exit 1; }; T=$(mktemp -d) && [ -d "$T" ] || { echo "לא הצלחתי ליצור תיקייה זמנית. לא הרצתי כלום."; exit 1; }; echo "$H"; echo '{"prompt":"טעית, כבר אמרתי לך"}' | CLAUDE_PROJECT_DIR="$T" python3 "$H" )

בשורה הראשונה מופיע שם ה-hook של הערכה שהותקן. אחריה צריכה להופיע ההנחיה שמתחילה ב-[טיפול בטעויות]. הבדיקה רצה בתיקייה זמנית, ולכן היא לא מוסיפה שורה ל-candidates.jsonl שלכם. הבקרה מריצה רק קובץ שזהה בדיוק ל-hook שבריפו. אם מופיע "לא נמצא hook זהה", ה-hook לא הותקן, או שהערכה עודכנה מאז ההתקנה ואז מתקינים שוב.

מודפסות השורות מ-7 הימים האחרונים, כולל היום, עם הקטע שסביב ביטוי התיקון. אם עוד אין קובץ, יופיע 0. תעברו על התיקונים שכתבתם השבוע, אחד אחד, ותבדקו שלכל אחד יש שורה. תיקון שלא נתפס אומר שחסר ביטוי ב-MARKERS בתוך ה-hook. תוסיפו את המילים שאתם באמת כותבים.

def lessons_dir(data):
    return os.path.join(os.environ.get("CLAUDE_PROJECT_DIR") or data.get("cwd") or os.getcwd(), "lessons")


def read_log(base):
    try:
        return open(os.path.join(base, "MISTAKES.md"), encoding="utf8").read()
    except OSError:
        return None


def pending_path(base, data):
    sid = re.sub(r"[^A-Za-z0-9_-]", "", str(data.get("session_id") or "nosession"))[:80] or "nosession"
    return os.path.join(base, f".pending_entry-{sid}.json")


def load_pending(path):
    """מחזיר (ids, corrupt). סמן פגום לא מתאפס: הוא נשמר בצד ומסומן, כדי שתיקונים קודמים לא ייעלמו מהמעקב."""
    if not os.path.exists(path):
        return [], False
    try:
        p = json.load(open(path, encoding="utf8"))
        ids = [str(i) for i in p["ids"]]
        return ids, bool(p.get("corrupt"))
    except Exception:
        keep = f"{path}.corrupt-{datetime.datetime.now().strftime('%Y%m%d-%H%M%S')}"
        os.replace(path, keep)
        return [], True


def save_pending(path, ids, corrupt):
    with open(path, "w", encoding="utf8") as f:
        json.dump({"ids": ids, "corrupt": corrupt, "ts": datetime.datetime.now().isoformat(timespec="seconds")}, f)


try:

if not text:

## טעויות
- כשאני מתקן אותך, תוסיף רשומה ל-lessons/MISTAKES.md לפי הפורמט, באותו רגע ולא בסוף הסשן. אם ה-hook נתן מזהה (#mk-...), תכתוב אותו ברשומה.

מה הערכה לא עושה

ה-hook מזהה רק את הביטויים שברשימה, ובודק רק את 1,500 התווים הראשונים של ההודעה. תיקון בסוף הודעה ארוכה לא נתפס. תיקון שכתוב אחרת לא נתפס, ולכן קיימת בקרה 5. כלל כתוב לא מבטיח כלום, ולכן קיימת בקרה 6. וגם היומן לא כותב את עצמו. אם קלוד מקבל את ההנחיה ולא רושם, בקרה 3 תראה את זה.
